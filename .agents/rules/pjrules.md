プロジェクト概要: comfyui-llamacpp-client

このプロジェクトは ComfyUI と llama.cpp を連携させるクライアントライブラリです。

ハードウェア・リソース環境

エージェントは以下の強力なリソースを前提に、最適化されたコードや推論処理を提案してください。

GPU: NVIDIA GeForce RTX 5090 (32GB VRAM)

Memory: 48GB DDR5 (24GB x 2)

OS: Windows (Dドライブに環境構築済み)

1. 開発・実行環境 (CRITICAL)

コマンドの実行やテストの際は、必ず以下の仮想環境を使用してください。

Python Path: D:\AI\ComfyUI\venv\Scripts\python.exe

Venv Path: D:\AI\ComfyUI\venv

Constraint: システム全体の Python は使用せず、必ず上記 venv 内のインタプリタまたは activate を使用すること。

2. 思考プロセスとプランニング

PLAN.md の運用: タスク開始前に @PLAN.md を読み取り、現在のステップを確認すること。また、プランを新規作成・更新した場合は、必ず @PLAN.md にその内容を出力し、常に最新の状態を維持すること。

履歴の記録: 重要な変更後は @REVISION_HISTORY.md に内容を追記すること。

タスク完了の明示とサマリ報告: 一連の作業（実装、デバッグ、テスト等）が完了した際は、必ず「タスク完了」を明示的に宣言すること。その際、変更したファイル、適用したロジック、確認したテスト項目などのサマリを箇条書きで簡潔に報告し、次のステップを提示すること。

設計優先: 複雑な修正では、まず設計案を提示し、ユーザーの承認を得てから実装を開始する。

情報の整合性: 冗長な進捗報告や重複した実装プランを避け、簡潔かつ正確に出力すること。

3. コーディング・技術規約

Python 規約:

async/await による非同期処理を基本とする。

Strict Typing: すべての新規/修正コードに Python Type Hints を付与し、mypy をパスさせる。

Documentation: 複雑なロジックには英語で明確な Docstring を記述すること。

ComfyUI 固有の仕様:

IMAGE テンソル: 必ず 4Dテンソル [Batch, Height, Width, Channels] (float32, 0-1 range) として扱うこと。

エラー処理: ネットワーク遅延、タイムアウト、API切断に対する堅牢なハンドリングを実装する。

4. テストと検証

Mock の活用: I/F や API クライアントのテストには、実サーバー接続を求めず unittest.mock 等を用いたモックベースのテストを実装すること。

検証報告: 修正完了後、pytest 等でテストを実行し、その結果を詳細に報告すること。

5. ツール操作の精度

パラメータの完全性: execute_command などのツールを呼び出す際は、requires_approval を含むすべての必須パラメータを省略せずに含めること。

6. 推奨されるUIモードとモデルの使い分け

AntigravityのUI機能（Planning / Fast）に合わせた推奨運用です。

Planning モード (設計・調査段階):

推奨モデル: Claude Sonnet 4.6 (Thinking) 等の高知能モデル

用途: @PLAN.md の策定、複雑なアーキテクチャ設計、エラーの根本原因分析。

Fast モード (実装・テスト実行段階):

推奨モデル: Gemini 3 Flash 等の高速・軽量モデル

用途: 確定したプランに基づくコード生成、ドキュメント作成、テストコードの記述。

エージェントへの重要指示:
プランニング（設計）が完了し、実際のコーディングやコマンド実行のフェーズへ移行する際は、ユーザーに対して「設計が完了しました。実装のためにUIを Fastモード（または軽量モデル） へ切り替えますか？」と確認を行ってください。
